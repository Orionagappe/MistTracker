## What Is Chaos Unchained?

Chaos Unchained is the complete integrated system comprising:

### Core Components

1. **MistTracker** - The causal reasoning substrate and reputation-based validation network
2. **Hyperbolic Cube Key** - The unpickable cryptographic interface for secure exchange operations
3. **The Adversary** - Systemically authorized antagonist with domain-limited influence
4. **Byzantine Validators** - Distributed consensus network with quorum-based decision making
5. **Audit Chain** - Immutable transaction record with cryptographic proofs

### Unifying Philosophy

All components operate on a single principle: **Systems prove themselves through adversarial pressure.**

- The Adversary doesn't attack the system; it *tests* it
- Validators prove their integrity by resisting corrupted inputs
- The hyperbolic key proves security through irreversibility
- Reputation flows from truthfulness, not convenience
- All participants benefit from system survival, even opponents

## Key Concepts

### The Ooze (The Adversary)
An entity explicitly authorized to:
- Attack a single domain at any time
- Corrupt claims, lie consistently, test security
- Convert to aligned posture if system faces extinction
- Prove that cooperation is natural under pressure

**Why this works**: The Ooze is the system *testing itself*. By surviving attacks from an authorized adversary, the system proves its design is sound.

### 1/0 Domain Reset
Architects and domain admins can reset their domain state (once per 12 months) with security council approval. Emergency exception: system-wide threat detection.

**Why this exists**: Acknowledges that measurement errors happen. Allows correction without permanent penalty.

### The Hyperbolic Key
A cryptographic interface using Poincaré disk geometry and Möbius transformations. Not a puzzle; an unpickable access method.

**Why hyperbolic**: Mathematics guarantees irreversibility. Users cannot reverse-engineer the key because Möbius transformations are one-way functions in negative-curvature space.

### The Symmetry of 17
Fundamental to system organization. Four-fold development (four validator classes, four domain groupings, four phases of trust establishment).

## Validator Hierarchy

### Architect Class
- Oversight authority across all domains
- Approve domain admin promotions
- Settle disputes between domains
- Can perform 1/0 resets (once per 12 months, with council approval)
- Self-accountability required: must demonstrate understanding of past failures

### Domain Admin Class
- Local authority within single domain
- Validate claims in their domain
- Promote validators to local positions
- Can perform domain-wide 1/0 resets (once per domain per 12 months)

### Validator Class
- Submit verdicts on claims
- Participate in quorum consensus
- Build reputation through truthfulness
- May be promoted to admin/architect

### Player Class
- Submit claims about measurements
- Gain/lose reputation based on accuracy
- Access secure exchange interface (if terms accepted)
- Participate in system governance through reputation

## Security Model

### Design Principle
**Transparency is not transparency unless it's adversarial.**

A system with perfect internal consistency proves nothing. A system that survives systematic attacks from an authorized adversary proves everything.

### Threat Model
Chaos Unchained assumes:
- Some validators may be compromised
- Some claims may be malicious
- Some domains may be under attack
- System must survive 1/3 corruption

### Defense Mechanism
- Byzantine consensus prevents single-point-of-failure verdicts
- Audit chain provides post-hoc accountability
- Reputation cost discourages lying
- Adversary tests for weaknesses continuously
- Security council reviews suspicious patterns
- 1/0 resets allow measured error correction
